# 小红书运营助手 — 产品需求文档（PRD）

> 版本：v1.0  
> 日期：2026-09-01  
> 产品阶段：MVP  
> 目标用户：个人博主 / 素人创作者

---

## 一、文档概述

### 1.1 产品背景

小红书已成为中文互联网最重要的「种草」和「生活方式决策」平台之一。大量素人创作者希望持续产出爆款笔记，但面临选题枯竭、文案能力弱、违规风险高、发布流程繁琐等问题。通用 AI 工具虽然能写文案，但不懂小红书平台调性、不提供合规检测、也无法接入发布工作流。

### 1.2 产品定位

> **最懂小红书的 AI 运营助手**  
> 从选题到发布，帮助用户高效产出合规、有爆款潜质的小红书笔记。

### 1.3 产品目标

| 目标 | 描述 | 衡量指标 |
|------|------|----------|
| **价值目标** | 让普通博主也能稳定产出高质量小红书笔记 | 人均生成次数、用户 NPS |
| **商业目标** | 验证 Freemium 订阅模式 | 付费转化率、MRR |
| **产品目标** | 建立「生成 + 合规 + 发布」最小闭环 | 生成 → 发布完成率 |

## 二、目标用户与用户画像

### 2.1 主要用户：个人博主 / 素人创作者

- **年龄**：18-35 岁
- **身份**：学生、职场新人、自由职业者、副业创作者
- **粉丝量**：0 - 5 万
- **核心诉求**：
  - 不知道写什么（选题难）
  - 写出来没人看（不懂爆款结构）
  - 怕违规被封号（合规焦虑）
  - 发布效率低（复制粘贴繁琐）

### 2.2 次要用户（后期）：腰部博主 / 小团队

- 需要批量生产内容
- 需要风格统一和合规风控
- 愿意支付更高费用

## 三、用户故事

### 3.1 内容生成

> 作为一名新手美妆博主，我输入「油皮夏季护肤」，选择「种草带货型」，系统能帮我生成 3 个标题、1 篇正文、5 个标签和 1 段封面文案，让我快速有内容可发。

### 3.2 合规检测

> 作为一名健康博主，我担心文案里出现违禁词或医疗功效承诺。我希望系统在生成后能自动标出风险，并告诉我怎么修改。

### 3.3 发布辅助

> 作为一名穿搭博主，我写好文案后不想再手动复制到小红书。我希望点击浏览器插件，就能一键填入标题、正文和标签。

### 3.4 模板学习

> 作为一名知识付费博主，我看到某篇爆款笔记很好，希望输入链接或粘贴内容，让 AI 学习其风格并生成类似文案。

## 四、功能需求

### 4.1 功能优先级总览

| 优先级 | 功能模块 | 阶段 | 说明 |
|--------|----------|------|------|
| **P0** | 爆款文案生成 | MVP | 核心功能，必须上线 |
| **P0** | 敏感词/合规检测 | MVP | 核心差异化 |
| **P0** | 用户账户与历史记录 | MVP | 基础能力 |
| **P1** | 浏览器插件半自动发布 | 上线后 1 个月内 | 提高工作流闭环 |
| **P1** | 对标笔记分析 | 上线后 1 个月内 | 增强模板学习能力 |
| **P1** | 模板库分类 | 上线后 1 个月内 | 提升生成质量 |
| **P2** | 真正一键自动发布 | 高级功能 | 需评估平台风险 |
| **P2** | 合规评分与模拟初审 | 高级功能 | 深度合规能力 |
| **P2** | 批量生成 | 高级功能 | 面向团队用户 |
| **P2** | 数据复盘 | 高级功能 | 发布后数据回流 |

### 4.2 P0 功能详细设计

#### 4.2.1 爆款文案生成

**入口**：Web 应用首页

**输入字段**：

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| 主题/关键词 | 是 | 文本 | 例如：油皮夏季护肤 |
| 目标受众 | 是 | 选择/文本 | 例如：20-30 岁女性、学生党 |
| 爆款类型 | 是 | 单选 | 干货收藏型 / 种草带货型 / 情绪共鸣型 / 争议讨论型 / 涨粉型 |
| 补充信息 | 否 | 文本 | 产品名称、使用场景、个人经历等 |
| 语气风格 | 否 | 单选 | 亲切 / 专业 / 幽默 / 犀利（默认亲切） |

**输出内容**：

| 输出项 | 数量 | 说明 |
|--------|------|------|
| 标题 | 3 个 | 不同角度，供用户选择 |
| 正文 | 1 篇 | 300-800 字，适配小红书阅读习惯 |
| 标签 | 5-10 个 | 结合主题和爆款类型 |
| 封面文案 | 1 段 | 用于封面大字或首图文字 |
| 发布建议 | 1 条 | 最佳发布时间、互动引导话术（简单版） |

**生成逻辑**：
- 根据爆款类型选择对应的 system prompt 模板。
- 输出前经过合规检测，命中高风险则拦截并提示。

---

#### 4.2.2 合规检测

**检测维度**：

| 维度 | 示例 | 处理方式 |
|------|------|----------|
| 敏感词/极限词 | 第一、最好、根治、祛斑 | 标红 + 修改建议 |
| 医疗/医美风险 | 治疗、疗效、医生推荐、前后对比 | 高风险拦截 |
| 金融投资风险 | 稳赚、保本、收益率、0 风险 | 高风险拦截 |
| 教育资质承诺 | 包过、保录取、学历提升 | 中风险提示 |
| 外部导流 | 微信、VX、手机号、二维码、外链 | 标红 + 建议删除 |
| 广告声明缺失 | 出现品牌/价格/优惠 | 提示添加 #合作 / #赞助 |

**风险等级**：
- **低风险**：直接输出
- **中风险**：输出 + 黄色警告 + 修改建议
- **高风险**：拦截 + 红色警告 + 明确原因

---

#### 4.2.3 用户账户与历史记录

- 支持邮箱/手机号注册登录。
- 保存用户生成的历史记录，支持复用、收藏、删除。
- 免费用户每日生成次数限制为 3 次。

---

### 4.3 P1 功能详细设计

#### 4.3.1 浏览器插件（半自动发布）

**目标**：在小红书创作服务平台/网页端实现一键填入。

**功能**：
- 登录后同步用户生成内容列表。
- 在小红书发布页注入「从助手导入」按钮。
- 点击后自动填入：标题、正文、标签。
- 封面图片仍需用户手动上传（小红书限制）。

**安全设计**：
- 插件本地保存用户小红书 session，不上传服务端。
- 发布操作由用户在浏览器内确认后触发。

#### 4.3.2 对标笔记分析

- 用户输入小红书笔记链接或粘贴正文。
- 系统分析其结构：标题类型、正文节奏、标签策略、情绪点。
- 生成「同款风格」的仿写建议。

#### 4.3.3 模板库

- 按品类分类：美妆、穿搭、美食、旅行、职场、知识付费等。
- 每个模板包含：适用场景、输入示例、输出结构。
- 支持用户收藏常用模板。

---

### 4.4 P2 高级功能（后续规划）

#### 4.4.1 真正一键自动发布
- 用户授权后，系统通过浏览器自动化/RPA 在本地完成发布。
- 明确风险提示，仅对高级会员开放。

#### 4.4.2 合规评分
- 对生成内容给出 0-100 合规分。
- 模拟平台初审结果：通过 / 需修改 / 高风险。

#### 4.4.3 批量生成
- 一次输入多个主题，批量输出多篇笔记。
- 面向 MCN 和矩阵账号运营。

#### 4.4.4 数据复盘
- 用户授权后读取发布数据。
- 分析标题、标签、发布时间对数据的影响。
- 反哺生成模型优化。

## 五、非功能需求

### 5.1 性能

| 指标 | 要求 |
|------|------|
| 文案生成耗时 | < 5 秒（90% 请求） |
| 页面首屏加载 | < 2 秒 |
| 并发支持 | MVP 阶段支持 100 QPS |

### 5.2 安全

- 用户密码加密存储（bcrypt）。
- 小红书 session 不存储在服务端（P1 插件本地保存）。
- 所有用户输入做 XSS 过滤。
- 敏感词规则库独立维护，支持热更新。

### 5.3 合规

- 用户协议明确 AI 生成内容仅供参考，发布责任由用户承担。
- 高风险类目内容必须拦截，不能放行。
- 遵守《生成式人工智能服务管理暂行办法》等相关法规。

### 5.4 可用性

- 支持主流浏览器：Chrome、Edge、Safari。
- 移动端 Web 可用（后期可考虑小程序）。
- 免费用户在次数用完后有清晰的付费引导。

## 六、用户流程

### 6.1 核心流程：生成一篇笔记

```
[打开 Web 应用]
    ↓
[登录 / 注册]
    ↓
[输入主题 + 受众 + 爆款类型]
    ↓
[点击生成]
    ↓
[系统调用 LLM 生成文案]
    ↓
[合规检测]
    ├── 高风险 → 拦截，提示修改
    ├── 中风险 → 输出，提示警告
    └── 低风险 → 直接输出
    ↓
[用户查看标题×3 + 正文 + 标签 + 封面文案]
    ↓
[用户选择满意版本]
    ↓
[复制 / 浏览器插件导入 / 保存历史]
```

### 6.2 浏览器插件发布流程

```
[用户安装浏览器插件并登录]
    ↓
[打开小红书创作服务平台发布页]
    ↓
[点击插件「导入笔记」]
    ↓
[选择历史记录中的笔记]
    ↓
[插件自动填入标题、正文、标签]
    ↓
[用户手动上传封面图]
    ↓
[用户点击小红书发布按钮]
```

## 七、页面与交互设计

### 7.1 Web 应用页面结构

| 页面 | 功能 |
|------|------|
| 首页 / 生成页 | 输入主题、选择类型、生成文案、查看结果 |
| 历史记录页 | 查看、收藏、复用、删除过往生成 |
| 模板库页 | 浏览、筛选、收藏爆款模板 |
| 对标分析页 | 输入链接/正文，分析并仿写 |
| 个人中心 | 账户信息、订阅状态、使用统计 |
| 帮助/合规说明 | 合规规则、用户协议、免责声明 |

### 7.2 核心页面元素

#### 生成页
- 顶部：品牌 Slogan + 今日剩余次数
- 左侧：输入表单（主题、受众、类型、风格、补充信息）
- 右侧：生成结果卡片（标题×3、正文、标签、封面文案）
- 底部：复制按钮、保存按钮、插件导入按钮（P1）

#### 结果卡片
- 每个标题可单独复制/收藏。
- 正文支持一键复制。
- 标签以 # 形式展示，可批量复制。
- 合规风险提示以颜色标签显示在卡片顶部。

## 九、API 设计

### 9.1 认证

- `POST /api/auth/register` 注册
- `POST /api/auth/login` 登录
- `POST /api/auth/logout` 登出
- `GET /api/auth/me` 获取当前用户

### 9.2 生成

- `POST /api/generate` 生成笔记
  - Request: `{ topic, audience, content_type, tone, extra_info }`
  - Response: `{ titles, body, tags, cover_text, compliance_result, remaining_quota }`

### 9.3 历史记录

- `GET /api/generations` 获取历史记录
- `GET /api/generations/:id` 获取单条记录
- `DELETE /api/generations/:id` 删除记录
- `POST /api/generations/:id/favorite` 收藏/取消收藏

### 9.4 模板

- `GET /api/templates` 获取模板列表
- `GET /api/templates/:id` 获取模板详情

### 9.5 对标分析

- `POST /api/analyze` 分析对标笔记
  - Request: `{ url? content? }`
  - Response: `{ structure_analysis, rewrite_suggestions }`

### 9.6 合规检测

- `POST /api/compliance/check` 单独检测文本合规性
  - Request: `{ text }`
  - Response: `{ risk_level, issues, suggestions }`

## 十四、风险与限制

### 14.1 技术风险

- **LLM 输出不稳定**：同一输入可能产生质量差异大的结果。
  - 应对：加 prompt 工程、输出后过滤、提供多个标题供选择。

- **合规检测误杀/漏杀**：规则太严影响体验，太松有风险。
  - 应对：建立规则反馈机制，持续优化。

### 14.2 合规风险

- **自动发布可能违反小红书 ToS**。
  - 应对：MVP 先上半自动，高级功能明确风险提示，本地保存 session。

- **AI 生成内容版权/责任问题**。
  - 应对：用户协议明确责任归属，提供免责声明。

### 14.3 商业风险

- **通用 AI 快速迭代可能削弱单点价值**。
  - 应对：做深工作流和数据飞轮，不单点竞争。

## 十六、附录 C：小红书笔记完整构成与产品输出扩展

> 本附录用于回答「小红书笔记分几类、有哪些组成部分、标题+正文+标签+封面文案是否足够」的问题，并据此扩展 PRD 中的产品输出规范。

### 16.1 小红书笔记的常见分类

#### 16.1.1 按内容形式分

| 形式 | 说明 | 特点 |
|------|------|------|
| **图文笔记** | 图片 + 文字 | 信息密度高、便于收藏、制作门槛较低 |
| **视频笔记** | 短视频 + 文字/口播 | 沉浸感强、平台流量倾斜、制作门槛较高 |
| **直播** | 实时互动 | 带货、答疑、涨粉，独立产品形态 |

#### 16.1.2 按内容目的/结构分

| 类型 | 核心目的 | 常见结构 |
|------|----------|----------|
| **种草带货型** | 推荐产品，激发购买欲望 | 场景 + 体验 + 卖点 + 购买引导 |
| **干货教程型** | 传授方法、技巧、攻略 | 痛点 + 步骤 + 案例 + 总结 |
| **合集清单型** | 汇总推荐，便于收藏 | 数字 + 清单 + 简要说明 + 互动 |
| **测评对比型** | 横向/纵向对比产品 | 维度 + 对比 + 结论 + 建议 |
| **情绪共鸣型** | 引发情感共鸣和讨论 | 故事 + 冲突 + 感悟 + 提问 |
| **Vlog/Plog 型** | 记录生活，建立人设 | 时间线/场景线 + 细节 + 情绪 |
| **故事分享型** | 通过个人经历吸引关注 | 背景 + 转折 + 结果 + 启示 |

#### 16.1.3 按爆款写作结构分

| 结构 | 说明 | 适用 |
|------|------|------|
| **AIDA** | Attention → Interest → Desire → Action | 种草、带货 |
| **4U** | Urgent → Unique → Ultra-specific → Useful | 促销、限时推荐 |
| **问题-解决型** | 痛点 → 方案 → 步骤 → 效果 → 总结 | 干货、教程 |
| **对比式** | 产品 A vs 产品 B，数据支撑，结论明确 | 测评 |
| **总-分-总** | 观点 → 分点论证 → 总结升华 | 观点、知识 |

### 16.2 一篇完整小红书笔记的组成部分

| 组成部分 | 是否必要 | 说明 |
|----------|:--------:|------|
| **选题** | ✅ 是 | 决定流量天花板，先于所有内容生产 |
| **封面（首图/视频首帧）** | ✅ 是 | 决定点击率，小红书第一注意力 |
| **封面文案** | ✅ 是 | 封面上的大字/核心信息，强化点击理由 |
| **标题** | ✅ 是 | 第二注意力，影响搜索和推荐 |
| **正文** | ✅ 是 | 承载核心价值，决定收藏/互动/转化 |
| **图片/视频（内容主体）** | ✅ 是 | 视觉内容，决定停留时长和信任感 |
| **标签/话题** | ✅ 是 | 流量分发入口，影响推荐精准度 |
| **定位/地点** | ⚠️ 视情况 | 本地生活、旅行、探店类笔记重要 |
| **@相关账号** | ⚠️ 视情况 | 合作、引用、互动时使用 |
| **音乐/音效/特效（视频）** | ⚠️ 视情况 | 提升视频完播率和氛围 |
| **评论区运营** | ✅ 是 | 置顶评论、自问自答、引导互动 |
| **发布时间与频率** | ✅ 是 | 影响冷启动流量 |

### 16.3 标题 + 正文 + 标签 + 封面文案够吗？

**不够。** 这四个要素只是笔记的「文本骨架」，缺少小红书最核心的视觉载体：

- **封面图**：决定用户是否点击（点击率）。
- **内页图片/视频**：决定用户停留时长、收藏率和互动率。
- **评论区运营**：决定笔记进入更大流量池的二次传播。

但是，作为 **AI 写作助手**，我们的价值定位不是替代 Canva/剪映 做图或做视频，而是：

> **把文字部分做到极致，并为视觉内容提供专业指导和素材脚本。**

### 16.4 产品输出应扩展为三层

基于以上分析，PRD 中 4.2.1 节的输出内容应扩展为：

#### 第一层：文本内容（AI 直接生成）

| 输出项 | 数量 | 说明 |
|--------|------|------|
| 选题方向 | 1-3 个 | 给用户选题灵感 |
| 标题 | 3-5 个 | 不同角度，含关键词优化 |
| 正文 | 1 篇 | 完整正文，含开篇钩子、中间内容、结尾引导 |
| 标签 | 5-10 个 | 核心标签 + 场景标签 + 长尾标签 |
| 封面文案 | 1-2 段 | 封面大字/核心卖点文案 |
| 评论区话术 | 1-2 条 | 置顶评论、互动引导 |

#### 第二层：视觉方案（AI 输出脚本/建议）

| 输出项 | 说明 |
|--------|------|
| 封面图设计建议 | 尺寸（3:4）、配色、人物/产品摆放、文字位置、安全区提示 |
| 内页图片脚本 | 每张图放什么内容、配什么文字、用什么构图 |
| 视频分镜脚本 | 镜头时长、画面内容、口播台词、BGM 情绪 |
| 封面/内页字体建议 | 字号、字体风格、重点高亮 |

#### 第三层：运营策略（AI 输出建议）

| 输出项 | 说明 |
|--------|------|
| 最佳发布时间 | 根据目标受众活跃时段建议 |
| 发布定位 | 是否添加地点、添加什么地点 |
| @建议 | 是否 @品牌方、相关账号 |
| 话题组合策略 | 核心话题 + 长尾话题配比 |
| 互动引导 | 结尾如何引导点赞/收藏/评论/关注 |

### 16.5 对 MVP 的取舍建议

| 层级 | MVP 是否必须 | 说明 |
|------|:------------:|------|
| 文本内容 | ✅ 必须 | 核心价值，必须做到位 |
| 封面图设计建议 | ✅ 必须 | 封面是小红书第一注意力，不能缺 |
| 内页图片脚本 | ⚠️ 建议有 | 提升产品完整度，但可用简单版 |
| 视频分镜脚本 | ❌ P1 | 视频功能可后续扩展 |
| 运营策略建议 | ✅ 必须 | 发布时间、话题、互动引导简单版 |

### 16.6 输出格式示例

未来产品生成结果可按以下结构呈现：

```markdown

## 标题
1. 油皮夏天的痛我懂！5步护肤让我不再油光满面
2. 救命！这套油皮夏季护肤流程真的好用
3. 油皮姐妹进！这个夏天这样护肤不踩雷

## 正文
（略）

## 封面文案

- 封面：3:4 竖图，左侧放护肤产品，右侧大字「油皮夏天有救了」，背景干净清爽。
```

## 十七、附录 D：图片如何处理？

> 本附录明确：在图文笔记场景下，产品不直接生成图片，而是输出「图片脚本 + 封面设计建议」，由用户自行拍摄/制作。图片生成能力作为 P2 扩展项。

### 17.1 为什么不直接在 MVP 生成图片？

| 原因 | 说明 |
|------|------|
| **成本** | AI 图片生成成本高于文本生成，免费用户难以覆盖。 |
| **质量** | 小红书图片需要真实感、生活感，AI 生成图容易被识别为「AI 味」，影响信任。 |
| **版权** | AI 生成图片的版权归属在不同平台和国家存在不确定性。 |
| **核心价值** | 我们的定位是「运营助手」，不是「设计工具」。图片脚本已经能大幅降低用户创作门槛。 |

### 17.2 MVP 图片输出规范

对于每一篇图文笔记，系统应输出以下图片相关指导：

#### 1）封面图设计建议

| 要素 | 说明 |
|------|------|
| **尺寸** | 3:4 竖图（小红书推荐） |
| **构图** | 主体清晰、留白适当、文字不超出安全区 |
| **配色** | 与笔记调性一致，推荐主色 + 辅助色 |
| **文字** | 封面文案的大字排版建议（字号、位置、颜色） |
| **元素** | 是否需要人物出镜、产品特写、对比图、数字标签等 |

#### 2）内页图片脚本

以一篇「油皮夏季护肤」笔记为例：

| 序号 | 图片内容 | 拍摄/设计建议 | 配文 |
|------|----------|---------------|------|
| 图 1 | 肤质自测 | 手机前置自然光，素颜或淡妆，标注「油皮特征」 | 先判断你是不是油皮 |
| 图 2 | 护肤产品平铺 | 干净背景，产品整齐摆放，有层次感 | 我的夏季护肤四件套 |
| 图 3 | 洁面步骤 | 手部特写，泡沫丰富，动作自然 | 第一步：温和清洁 |
| 图 4 | 精华/乳液使用 | 产品挤在手背或脸上，光线柔和 | 第二步：控油保湿 |
| 图 5 | 前后对比或注意事项 | 同一光线、同一角度，避免夸大功效 | 坚持 2 周的效果 |

#### 3）图片数量建议

- 一般图文笔记：**5-9 张**
- 教程/步骤类：**6-9 张**
- 种草/推荐类：**4-6 张**
- 情绪/故事类：**3-5 张**

### 17.3 用户可以怎么获取图片？

| 方式 | 适用场景 | 产品侧支持 |
|------|----------|------------|
| **用户自己拍摄** | 真实感最强，种草/测评类必备 | 提供拍摄脚本和构图建议 |
| **使用设计模板** | 清单、攻略、知识类 | P2 可接入 Canva/稿定设计模板 |
| **AI 图片生成** | 封面图、概念图 | P2 可接入 Midjourney/SD/DALL-E |
| **图库素材** | 通用场景图 | P2 可接入 Unsplash/摄图网等 API |

### 17.4 图片与合规的关系

- 封面图和商品图不能含有夸大功效、医疗暗示、虚假宣传。
- 对比图（before/after）在小红书属于高风险内容，系统应提示用户谨慎使用。
- 图片中如果出现品牌 logo、价格、购买渠道，应提示用户标注广告/合作声明。
